## Highlights

ProPR 0.9.3 adds two Gemini 4 models, updates the bundled coding agents, and makes follow-ups, CI failures and bot comments more reliable. Full details: [What's new in 0.9.3](https://propr.dev/whats-new/0.9.3/) and the [changelog](https://github.com/integry/propr/blob/v0.9.3/CHANGELOG.md).

**Agents and models**
- **Gemini 4 Neon** and **Gemini 4 Carbon** in the Antigravity catalog (aliases `neon` and `carbon`). Carbon needs a Google AI Ultra subscription with `agy login`.
- Bundled CLIs: Codex 0.170.0, Claude Code 2.1.328 and Antigravity CLI 1.5.12; OpenCode stays on 1.19.6 and Mistral Vibe on 2.25.8.
- OpenCode GLM 5.3 Flash Free is gone from OpenCode Zen; saved selections run DeepSeek V4.1 Flash Free.

**Follow-ups and CI failures**
- Follow-up comments are always picked up, including on pull requests ProPR opened through its retry path.
- Follow-up runs no longer fail with "a branch named … already exists".
- While a follow-up suspends CI, the pull request says so. A failure that only shows a runner or network problem no longer starts a code follow-up; the status block tells you to re-run the failed jobs instead.
- The CI-failure comment adds a line to a failed job that depends on other failed jobs, naming them so they are checked first.

**Pull requests and comments**
- A run that committed its changes but could not open its pull request is reported as failed, with a comment naming the step that failed.
- A run that ends while the agent says it is still waiting is flagged as unconfirmed instead of a clean success.
- Rate-limit, cancelled, started and merge-conflict notices post one comment and update it, and the rate-limit notice shows the right reset time, including weekly resets.
- `AI` and `llm-*` labels are applied once.
- The PR status line skips check-count edits when the GitHub App is close to its rate limit.

**Web UI**
- Automation run previews show each report's first sentence instead of the repeated title, and the run list columns line up.
- Larger tap targets on touch layouts, running follow-ups shown as Running in Maintenance, and readable type labels and model names in the LLM Log.

**Releases**
- Every GitHub release starts with a checked-in summary like this one, and a release rollout check and workflow show where a release is live.

## Upgrade notes

- No manual steps are expected.
- **Vendored picomatch builds are gone:** ProPR installs upstream picomatch from npm again. In a source checkout, run `npm ci` after pulling.
- **Failed publication:** a run whose changes were committed but whose pull request was not opened now ends as failed (`publication_failed`), and its issue keeps `AI` without getting `AI-done`.
- **Unconfirmed runs:** comments for runs that end while the agent is still waiting now read "AI Processing Ended Unconfirmed" or "⚠️ Committed follow-up changes". This needs a summarization model to be configured.
- **Automation run previews:** `reportPreview` in the API, the MCP `list_automation_runs` tool and the CLI now holds the report's first sentence rather than its title.
- **Existing pull requests without the `AI` label** still need it added by hand before plain follow-up comments on them are accepted.
